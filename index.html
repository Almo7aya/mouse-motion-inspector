How to test, and what these measurements mean

A useful comparison

  1. Keep the browser, Windows pointer speed, acceleration setting, and polling rate unchanged. Disconnect other pointing devices if possible.
  2. Enter the surface and actual DPI from Synapse. Run a 60-second test without touching the mouse or desk.
  3. Repeat 2–3 times, then try another surface at the same DPI. After that, compare DPI settings on the same surface.
  4. Do not change DPI or lift the mouse during a recording. Stop and start a new run. Mark accidental touches in your notes before repeating.
  5. Export all tests as JSON to share the complete record. CSV summaries are convenient for a spreadsheet.

Higher DPI can amplify the same physical movement. Compare repeatability and timing as well as travel; these numbers alone cannot diagnose a faulty sensor.

Browser measurements, with clear limits

  • Visible cursor: changes in clientX/clientY, in CSS pixels. OS acceleration and pointer speed apply. Capture stops if the cursor leaves the page, the window loses focus, or the tab is hidden.
  • Locked modes: the cursor is hidden and movement is not limited by screen edges. “Unadjusted requested” asks the browser to bypass OS acceleration; support varies and cannot be independently verified here. Failure is reported without switching modes.
  • Locked movement uses browser-reported units. These are not guaranteed hardware counts, millimetres, or CSS pixels. Do not compare their distances directly with visible-cursor tests.
  • The browser may merge or omit movement reports. Event rate is not USB polling rate. No detected motion means only that no nonzero movement reached this page. Other mice, a touchpad, or software can also move the pointer.
  • No nonzero-event threshold or smoothing is applied to recorded samples. Long traces are simplified for drawing only. A run stops at 100,000 samples; exports contain every recorded sample.
